# Issue #79 prototype acceptance

These are tests of a sanitized design/reference prototype. They do not
implement the production fixtures (#80), query/view-model layer (#81), Windows
GUI, campaign discovery, or slot-vacancy reconciliation (#122).

## Local checks

Run `node --test tests/presentation-contract.test.mjs tests/browser-acceptance-contract.test.mjs`.
The presentation tests exercise real view-model values. Checker mutation tests
use one captured Dossier row and deliberately corrupt its measurements. They
are replay tests, not a claim to have opened a browser.

Build the Site and run `node --test tests/rendered-html.test.mjs` for the Worker
SSR smoke test and source-boundary checks. The app-only type check is
`node node_modules/typescript/bin/tsc --noEmit --incremental false --project tests/tsconfig.acceptance.json`.

## Fresh rendered acceptance

Start the supervised Sites preview and use its internal URL. Begin from a
fresh page with the RFC demonstration career. Import `acceptanceCases` and
`runAcceptanceCase` from `browser-acceptance.mjs` into the browser driver
environment. The required adapter is the documented control-browser
`tab.playwright` locator/evaluate API plus `tab.cua.keypress`.

Execute each case, in order, in bounded batches:

```js
const row = await runAcceptanceCase(tab, acceptanceCases[index]);
```

Persist the returned observations, not a hand-written success flag. The driver
selects fixtures through visible controls, verifies the selection, reads only
DOM/computed-style state, and actually presses every Tab stop. It never writes
DOM values, reads React internals, forces clicks, or manipulates hidden state.
The case list covers 60 screen/profile pairs, 14 Dossier source states, 12 status
inputs, 28 complete Tab sequences, four allowed state actions, the full modal,
and same-name isolation in mission/aircrew/report contexts.

Profiles change the logical canvas; this is not a native Windows DPI test.
Their caps are 1440×1024, 1152×819, 960×683, and 720×512. The actual host viewport
is recorded separately. Native toolkit/DPI verification remains future work.

Collect `observePaint(tab)` from `paint-observations.mjs` on each rendered case.
Run `python tests/contrast_bounds.py < paint-observations.json` with Pillow
available. This calculator uses the actual texture crop under each text box,
conservative gradient/alpha/inset-shadow bounds, and both sides of solid
control boundaries. It fails closed for unsupported paint operations.
Scroll-clipped text outside texture coverage is reported separately; it is
never assigned a fabricated passing ratio. These bounds are not screenshot
pixel sampling and do not claim exact anti-aliasing values.

The three texture assets must retain the hashes recorded in the immutable
Audit 4 evidence. No screenshot thumbnail is regenerated by this workflow.

Archive a new evidence revision whenever source changes. Replaying an old JSON
capture in Python CI verifies its internal contract and hashes, not the mutable
public Site. Audit 1–3 are historical; their success claims do not substitute
for the executable measurements added here.
